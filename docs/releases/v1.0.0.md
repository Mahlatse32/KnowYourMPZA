# KnowYourMPZA v1.0.0

**Release date:** 2026-06-10
**Branch:** `main`
**Tag:** `v1.0.0`

---

## 1. What this release is

KnowYourMPZA v1.0.0 is the first public release of a **source-backed South
African political data platform**. It is a structured, evidence-backed database
of Members of Parliament, parties, committees, PMG documents, parliamentary
questions, and source evidence.

The core rule of this platform:

> Every political fact must answer: "How do we know this?"

V1 is **not** an AI chatbot. It is the data layer that makes accountable,
source-backed political intelligence possible.

---

## 2. Core features

- Source-backed MP profiles with party, committee memberships, and aliases
- Parliamentary Monitoring Group (PMG) document ingestion with politician mentions
- Parliamentary questions ingestion with PDF extraction and source archiving
- People's Assembly MP profile ingestion with photo URLs and profile evidence
- Entity resolution: messy name variants resolve back to canonical MP records
- Unresolved entity review workflow for manual cleanup
- Quality reporting: data health checks, duplicate detection, archive gap detection
- Ingestion run and error tracking for every batch
- Raw HTML and PDF archiving so source material is preserved locally
- Public React frontend for search, browsing MPs, parties, committees, documents, and questions
- Guarded scheduled ingestion via GitHub Actions (daily + weekly)
- CI pipeline: backend tests with PostgreSQL + frontend build check

## 6. Quality and admin capabilities

- `GET /quality/summary` — totals and counts across all entity types
- `GET /quality/issues` — structured cleanup queue (MPs without parties, etc.)
- `GET /quality/duplicates` — duplicate candidate detection
- `GET /quality/archive-gaps` — documents without local archive copies
- `python scripts/quality_check.py` — CLI quality report
- `python scripts/dataset_report.py` — milestone tracking JSON report

---

## 7. Known limitations

- MP coverage is partial (~133 politicians, ~188 committees, ~526 memberships at release). Full Parliament coverage requires additional ingestion runs.
- Parliamentary question coverage is limited (~55 questions at release). Scaling requires bulk question discovery and ingestion.
- ~244 unresolved entities exist from committee and document parsing. These require manual review via the API.
- Raw archives are stored on local disk. Cloud (S3-compatible) archive storage is stubbed but not yet implemented.
- PDF text extraction relies on pypdf; scanned/image PDFs will not extract text.
- Entity resolution uses alias matching; very unusual name formats may still fail to resolve.
- No authentication, rate limiting, or API versioning on public endpoints. Not production-hardened for high traffic.

---

## 8. What is not included in V1

The following are **intentionally excluded** from V1:

- AI, LLM summaries, or chatbot features
- Bills and bill tracking
- Voting records
- Attendance records
- Topic tagging or classification
- OpenSearch or advanced full-text search
- pgvector or semantic search
- Authentication or user accounts
- Payments
- Mobile app
- S3-backed cloud archive storage (stubbed only)
- API versioning
- Rate limiting

## 9. Roadmap after V1

**Data coverage (next)**
- Expand MP coverage to 300–400 politicians
- Scale PMG documents to 500+
- Expand parliamentary questions to hundreds/thousands
- Clean unresolved entities

**Data quality**
- Implement cloud archive storage
- Improve PDF parsing for scanned documents
- Add topic tagging (rule-based first)

**New datasets (later)**
- Bills and bill stages
- Voting records
- Committee attendance

**Infrastructure**
- API rate limiting
- API versioning
- Production monitoring and alerting

**AI layer (after dataset is strong)**
- MP summaries citing source records
- Topic summaries
- Weekly intelligence briefs
- Natural language research assistant
- AI must always cite source-backed records — never free-standing assertions
